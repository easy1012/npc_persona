01 / Architecture

System Architecture

전체 구조는 `rsc/data`에서 시작해 Neo4j와 Streamlit을 거쳐 NPC 답변으로 끝난다. 런타임은 quest decision을 먼저 계산하고, 그 결과로 허용된 KnowledgeChunk만 prompt에 넣는다. 발표에서는 LLM 호출 세부 주소나 비밀값을 말하지 않고, 안전한 공개 표현으로 “vLLM 호환 응답 계층”만 표시한다. 핵심은 사용자의 한 턴이 LangGraph 판정, graph-scoped retrieval, prompt assembly, response logging 순서로 진행된다는 점이다.

02 / Story Source

Canonical Story Data

스토리의 기준은 언제나 `rsc/data`다. NPC Markdown은 프로필과 지식 블록을 제공하고, Quest YAML은 진행 규칙과 정답 공개 정책을 제공하며, World YAML은 clue, truth, role, event ID 계약을 제공한다. `chief_rowan`, `truth_moonwell_mana_cycle`, `answer_sensitive` 같은 값은 런타임 gate에 직접 연결되므로 단순 발표 문구가 아니다. 특히 `NPC-[:KNOWS]->KnowledgeChunk` 관계는 NPC가 실제로 말할 수 있는 지식의 시작점이다.

03 / Transform Paths

Importer And Pipeline

이 장은 같은 원천에서 갈라지는 두 경로를 구분한다. Direct importer는 `rsc/data`를 읽어 Neo4j runtime graph에 NPC, Quest, Clue, Truth, KnowledgeChunk를 병합한다. Offline pipeline은 같은 원천을 통합 데이터와 import artifact로 만들고 검증한다. 그래서 발표 문장에는 “Direct importer”와 “Offline pipeline”을 반드시 함께 두되, 두 결과가 같은 runtime 표면이라고 말하지 않는다. Neo4j reset requires explicit approval라는 안전 문구도 이 경로에서 고정한다.

04 / Graph Contract

Neo4j Graph Contract

Neo4j graph contract의 중심은 NPC와 KnowledgeChunk다. `NPC-[:KNOWS]->KnowledgeChunk`에서 시작해 quest, role, hint, answer gate 조건을 통과한 조각만 prompt context가 된다. 이 장은 관계 이름을 단순 장식이 아니라 retrieval 안전 규칙으로 설명한다. `answer_sensitive`, `allowed_hint_level`, `answer_reveal_allowed`는 각각 spoiler 위험, 현재 힌트 상한, 최종 공개 허용 여부를 나타내며, 세 조건이 함께 맞아야 민감 지식이 열린다.

05 / Runtime Turn

Streamlit Runtime

Streamlit runtime은 한 번의 사용자 입력을 세션 상태, quest decision, retrieval, prompt, 응답, 로그로 연결한다. 공개 deck에서는 내부 접속 문자열과 비밀 기본값을 제거하고, 흐름과 계약만 남긴다. 중요한 공개 사실은 session-only memory, chat log contains only input/output, 그리고 retrieval/prompt/quest/memory 로그가 관심사별로 분리된다는 점이다. 메모리는 NPC별로 분리되어 대화 맥락을 돕지만 Neo4j 영속 지식으로 취급하지 않는다.

06 / Quest State

LangGraph Quest Progression

LangGraph는 여기서 자유로운 agent planner가 아니라 deterministic quest runner다. `StateGraph`는 사용자 발화와 observed clue map을 받아 `QuestDecision`을 만들고, `InMemorySaver`로 thread별 단서 연속성을 지킨다. `QuestDecision`에는 state, `allowed_hint_level`, observed clues, route target, reveal truth, guidance가 함께 들어간다. 로완 final gate는 `chief_rowan`이 충분한 선행 quest와 정답 연결을 확인했을 때만 `truth_moonwell_mana_cycle` 공개를 허용한다.

07 / Prompt Safety

Prompting And Retrieval

Prompting layer는 이미 gate된 KnowledgeChunk와 QuestDecision guidance를 합쳐 NPC가 말해도 되는 정보만 자연스러운 한국어 대사로 말하게 한다. retrieval gate는 NPC match, role match, quest match, `allowed_hint_level`, `answer_sensitive`, `answer_reveal_allowed`를 모두 본다. prompt는 chunk metadata를 그대로 보여주지 않고 제목과 본문만 사용한다. final reveal은 quest rules, retrieval gate, prompt policy가 동시에 열릴 때만 허용된다.

08 / Admin Surface

Admin UI

Admin UI는 메인 NPC 채팅 화면과 분리된 Streamlit page다. Memory Admin은 NPC별 session memory count와 초기화를 다루고, Quest Admin은 quest state를 저장하며 hint level은 state에서 자동 계산한다. Concept Story Admin은 `ConceptStory` 노드를 별도로 조회하고 병합한다. 발표 문구는 ConceptStory is admin-only를 분명히 말해야 한다. 일반 NPC retrieval에 ConceptStory를 섞어 설명하면 runtime contract가 흐려진다.

09 / Deployment

Docker And Deployment

Deployment 장은 default compose and design-test compose are separate라는 사실만 공개 deck에 남긴다. 두 stack은 Streamlit, Neo4j, optional local model service를 갖지만 목적, volume, host binding, 검증 용도가 다르다. 발표 자료에서는 구체 포트, 네트워크 주소, 모델 이름, 비밀 기본값을 노출하지 않는다. 대신 “기본 운영 stack”과 “발표 검증 stack”을 나란히 보여 주고, Neo4j reset requires explicit approval라는 승인 gate를 하단 warning으로 고정한다.

10 / Evidence

QA And Test Artifacts

QA 체계는 source contract test와 live scenario evidence를 분리한다. prompt, Streamlit, quest auto progression, conversation tests는 drift를 막고, live 검증은 실제 11턴 대화에서 retrieval safety와 답변 품질을 확인한다. 공개 deck에는 QA PASS: 11 turns / 30 KnowledgeChunks라는 결론을 넣되, 모델명과 호출 주소는 넣지 않는다. 중요한 메시지는 final 전에는 answer-sensitive chunk와 최종 truth가 막히고, final에는 로완이 정답 연결을 직접 말한다는 양방향 검증이다.
